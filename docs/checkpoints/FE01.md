## 1. Tujuan

FE01 membangun boundary identity browser dan workspace yang selalu memakai actor serta Class context. Implementasi frontend boleh maju dengan contract snapshot dan mock, tetapi tidak boleh mengklaim login production atau integrasi penuh sebelum browser identity bridge, CSRF bootstrap/refresh, actor profile, dan daftar Class bercapability tersedia dari backend.

FE01 tidak mengimplementasikan create/edit/lifecycle/participant workflow. Pekerjaan domain tersebut tetap milik FE02.

### Keputusan login sementara — 10 September 2026

UI challenge-only dinonaktifkan karena challenge saja belum dapat menyelesaikan login. Field Email dan Password tetap tampil sebagai referensi disabled; tombol provider-netral `Lanjutkan ke Login Aman` tetap terlihat tetapi selalu disabled dan tidak memanggil transport challenge. Panel statis menjelaskan bahwa login menunggu integrasi identity owner. Typed challenge transport dipertahankan untuk flow final, tetapi tidak dipanggil oleh UI sementara.

Google tetap menjadi SSO awal di identity owner, bukan integrasi SDK/token di frontend. Flow final tetap: frontend meminta challenge via same-origin API, redirect hanya ke identity owner yang di-allowlist, identity owner memvalidasi verified identity dan immutable Google subject, callback menerima opaque one-time code yang terikat nonce dan berumur singkat, backend menukar code serta menetapkan cookie `Secure`, `HttpOnly`, dan `SameSite`, lalu CSRF bootstrap/refresh mengaktifkan mutation dan session controls. Google token, session token, assertion, dan nonce tidak boleh masuk browser storage atau Authorization header.

Untuk mempercepat pengembangan UI, tersedia preview eksplisit melalui `npm run dev:preview`. Flag `LMS_DEV_PREVIEW` hanya dibaca server dan hanya diterima saat `NODE_ENV=development`; actor serta Class fixture typed disuntikkan ke provider yang sama, sementara query identity/Class dan seluruh session command dinonaktifkan. Preview memakai output `.next-preview` terpisah, menampilkan banner permanen, dan tidak mengubah transport atau kontrak production. Matikan preview untuk kembali ke integrasi backend normal.

### Keputusan enrollment dan pencarian Class — 10 September 2026

Enrollment v3 tetap **assigned-only**. Admin dapat menambahkan Teacher atau Student, sedangkan Teacher hanya dapat menambahkan Student bila contextual capability participant management dari backend mengizinkan. Student tidak dapat self-enroll; frontend tidak menyediakan katalog Class global, enroll key, atau aksi join.

Pada `/app`, kontrol pemilihan Class diganti menjadi pencarian atas daftar actor-scoped dari `/me/classes`. Pencarian hanya memfilter Class yang sudah diikuti Student dan tidak melakukan global discovery. Setelah masuk ke `/app/classes/[classId]`, sidebar tidak lagi menampilkan pencarian Class maupun menu Workspace; keduanya diganti link `Back to Workspace` yang kembali ke `/app`. URL `classId` tetap menjadi source of context dan backend tetap menjadi authorization boundary.

### Revisi Ringkasan Class dan navigasi — 10 September 2026

Ringkasan `/app/classes/[classId]` memakai pola dashboard informatif: header konteks Class, program/cohort, role, status partisipasi, satu menu utama menuju Pembelajaran, daftar Tugas Mendatang, Pengingat Logbook, dan panel informasi Class. Tiga shortcut Pembelajaran/Orang/Pengumpulan lama dihapus dan UI tidak menampilkan progress.

Daftar tugas dan logbook menggunakan typed UI-facing adapter model, bukan field baru yang diklaim sudah tersedia pada OpenAPI. Fixture berisi status serta tenggat hanya disuntikkan pada development preview. Production tanpa read model menampilkan dependency state eksplisit dan tidak mengarang data. Integrasi tugas tetap menunggu M07/M08, sedangkan periode/status logbook menunggu M12; masing-masing tetap dibatasi capability `content.read` + `submission.read` dan `logbook.read`.

Sidebar hanya memberi active state pada route yang sedang dikunjungi. Ringkasan memakai exact match, sedangkan submenu boleh tetap aktif untuk child route-nya. Progress tidak diekspos sebagai menu. Policy `progress.read` pada direct URL lama tetap fail-closed agar penghilangan menu tidak diperlakukan sebagai authorization boundary.

## 5. Stop condition

Hentikan jalur terkait dan catat blocker bila implementasi memerlukan salah satu hal berikut:

- mengubah backend dari pekerjaan frontend;
- memperlakukan signed assertion lab sebagai opaque browser code;
- menyimpan session, CSRF, challenge, assertion, atau auth code di URL/localStorage/sessionStorage;
- menambahkan Authorization/Bearer fallback;
- mengarang `/me/classes`, authorization URL, actor profile, capability, atau CSRF refresh sebagai kontrak production;
- memakai role global sebagai pengganti capability Class;
- mengaktifkan mock pada production build.

Backend yang belum lengkap tidak menghentikan komponen, provider, transport, policy, dan mock QA yang tidak mengarang production integration.

### Brief testing untuk development lanjutan

Setiap perubahan lanjutan wajib menambahkan unit/component test untuk logic dan state yang diperkenalkan, lalu mempertahankan mandatory journey Playwright sebagai exit gate milestone. Untuk flow yang menunggu backend, fixture, empty, dependency, negative, capability, dan timezone state tetap diuji sekarang; setelah contract tersedia, adapter yang sama harus diuji terhadap response nyata dan journey HTTPS wajib dijalankan end-to-end.

FE01-T13 yang masih tertunda adalah mandatory integration journey, bukan unit test. Seluruh unit/component test FE01 saat ini sudah lulus, tetapi hasil tersebut tidak dapat membuktikan redirect identity owner, opaque-code exchange, cookie/CSRF browser, `/me/classes`, dan logout terhadap backend nyata.
