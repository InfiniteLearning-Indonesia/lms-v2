## 1. Tujuan

FE07 menyiapkan surface operasional Site Admin untuk administrasi identity, report/export, audit, durable job visibility, serta migration/cutover evidence tanpa memberi browser kewenangan operator atau mengklaim readiness yang belum dibuktikan.

Backend M13–M15 masih `NOT_STARTED`; M16–M17 tertahan input/approval dan M18 menunggu pilot. Karena itu FE07 dimulai sebagai UI-first yang production fail closed. Fixture development hanya membuktikan presentasi, bukan provider delivery, export, migrasi, rehearsal, pilot, atau rollout.

## 2. Keputusan product dan UX yang dibekukan

- Pertahankan route canonical yang sudah ada: `/app/admin/users`, `/reports`, `/audit`, dan `/migrations`. `/app/admin/classes` tetap milik FE02.
- Admin navigation menampilkan route secara exact-active dan capability-driven. Label Site Admin atau boolean `site_admin` bukan pengganti capability final.
- Job center tidak menjadi menu/sidebar baru sebelum kontrak canonical tersedia. Status job tampil kontekstual di Reports dan Migrations melalui komponen bersama.
- `/users` mengelola identity global dan invitation/provisioning; membership Teacher/Student per Class tetap berada di `/classes/[classId]/people`.
- Identity owner tetap authoritative untuk verified identity, immutable subject, invitation/reset, dan profile authority. Frontend tidak mengelola password atau Google token.
- Daftar user memakai progressive disclosure: search/filter → row/card → detail/history. Field PII hanya tampil dari explicit allowlist response.
- Report memakai actor-specific projection backend. Frontend tidak menggabungkan data Class, menghitung aggregate sensitif, atau membuat CSV authoritative dari cache browser.
- Export selalu private dan asynchronous. UI hanya menampilkan request/receipt/job/download state yang diizinkan; signed URL tidak disimpan di browser storage.
- Audit bersifat immutable dan read-only. Tidak ada edit/delete/repair dari halaman audit; filter tidak boleh mengubah makna atau menutupi failure history.
- Job state canonical mengikuti server (`queued`, `running`, `succeeded`, `partial`, `failed`). Progress, retryability, attempts, dan receipt tidak direkonstruksi dari timer browser.
- Migration dashboard memisahkan **code readiness**, **data/reconciliation**, dan **ownership/cutover**. Satu status hijau tidak boleh menyimpulkan ketiganya siap.
- `CLASS_MOVED`, maintenance, read-only fence, stale tab, dan safe retry adalah state eksplisit. Dirty form tidak boleh diam-diam dibuang ketika ownership berubah.
- Quarantine, partial, blocked, skipped, unknown, atau missing evidence tidak dipromosikan menjadi success.
- Migration/cutover control plane tetap operator-only di backend/ops. FE07 tidak menyediakan tombol copy database, switch writer, deploy, restore, purge, delete, atau traffic flip.
- Seluruh copy baru masuk katalog `next-intl`; desktop table mempunyai mobile card/detail fallback dan control interaktif minimum 44 px.

## 3. Baseline flow

### 3.1 User dan invitation

```text
Admin Users
  → search/filter identity global
  → buka detail actor-scoped
  → lihat account/profile/invitation/session summary yang diizinkan
  → susun invitation atau account-state intent
  → final command menunggu M04 + CSRF/version/idempotency/receipt
```

Membuat identity tidak otomatis mendaftarkan actor ke Class. Assignment Class tetap melalui FE02 dan backend M05.

### 3.2 Report, export, dan job

```text
Admin Reports
  → pilih report/scope/filter yang didukung backend
  → lihat projection paginated + watermark/version
  → minta private export
  → terima durable receipt/job ID
  → pantau queued/running/succeeded/partial/failed
  → download hanya setelah authorized private access tersedia
```

Tidak ada instant-success, fake percentage, atau browser-generated full export pada UI-first.

### 3.3 Audit

```text
Admin Audit
  → filter waktu/actor/action/resource/outcome/request ID
  → baca stable cursor page
  → buka detail event yang field-nya sudah disanitasi backend
  → ikuti correlation/receipt reference bila capability mengizinkan
```

Audit log adalah evidence, bukan authorization source dan bukan command surface.

### 3.4 Migration dan cutover

```text
Admin Migrations
  → baca code/data/ownership readiness secara terpisah
  → pilih unit/Class dari projection yang diizinkan
  → tinjau preflight, backup, mapping, conflict, reconciliation, dan file disposition
  → tinjau rehearsal/restore timing dan unresolved approvals
  → baca fence/owner epoch, maintenance, pilot, dan wave evidence
  → status final hanya mengikuti backend + human approval authoritative
```

UI tidak men-trigger migration, rehearsal, pilot, rollout, atau ownership switch.

## 4. Scope

### 4.1 Masuk scope

- Capability-driven Admin navigation dan route guards untuk Users, Reports, Audit, dan Migrations.
- Typed actor-scoped view model/schema untuk user directory/detail, reports, audit events, jobs, dan migration/cutover evidence.
- User search/filter/detail/history, invitation/account-state form shell, last-admin/identity-owner dependency state, dan disabled final commands.
- Report catalog/parameter shell, bounded pagination/filter/sort presentation, watermark/freshness, empty/unavailable state, private export request shell.
- Shared job status list/detail untuk report/export dan migration evidence, termasuk attempts, failure/partial state, retryability, dan durable receipt presentation.
- Immutable audit list/detail dengan cursor/filter, request/correlation identity, redacted/private field state, dan no-edit boundary.
- Migration overview untuk code/data/ownership, preflight/backup/mapping/reconciliation/quarantine, rehearsal/recovery, fence/read-only, pilot/wave/approval evidence.
- Global `CLASS_MOVED`, maintenance/read-only, stale capability/tab, safe retry, dan dirty-state guidance.
- Development-only typed fixture; production dependency state tanpa invented request; unit/component/E2E/accessibility/responsive/security checks.

### 4.2 Di luar scope

- Implementasi atau perubahan repository backend M04/M13–M18.
- Password/Google SDK/token handling, provider secrets, invitation delivery, notification preference/provider, atau AI execution.
- Browser-side authoritative reporting/aggregation, public export URL, signed URL persistence, atau automatic download tanpa access check.
- Audit mutation, history purge, dead-letter purge, receipt rewrite, provider retry command tanpa canonical policy.
- Migration CLI/API, source copy, DB/file mutation, backup/restore, rehearsal execution, ownership switch, traffic routing, deployment, pilot, atau rollout approval.
- Legacy deletion, database/schema cleanup, `DELETE`/`TRUNCATE`/`DROP`, automatic rollback setelah first v3 write, atau status readiness buatan frontend.

## 8. Stop condition

- Jangan mengaktifkan invitation/account/export/retry command atau typed business transport sebelum OpenAPI, capability, CSRF, version/idempotency, receipt, dan error semantics direview.
- Jangan menampilkan field identity/report/audit/job/migration di luar allowlist actor-scoped atau menyimpannya ke browser storage.
- Jangan membuat aggregate/export/audit repair/job progress/readiness di browser untuk mengisi contract gap.
- Jangan menampilkan signed URL, provider secret/raw response, invitation/reset token, backup locator, DB credential, atau operational identifier sensitif.
- Jangan memberi frontend kemampuan memulai migration/rehearsal/fence/switch/deploy/pilot/wave atau operasi destruktif apa pun.
- Jangan menyebut migration, rehearsal, pilot, rollout, restore, RTO/SLO, atau release siap berdasarkan fixture/local UI.
- Jangan menandai FE07 `COMPLETED` sebelum D06/D08 dan FE07-T14 mempunyai evidence backend/identity/ops nyata.
- Jangan mengubah backend, commit, push, deploy, atau memperluas scope FE08 dalam implementasi FE07 tanpa instruksi baru.
