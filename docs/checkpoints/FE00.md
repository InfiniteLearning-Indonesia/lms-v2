[Master plan](../FRONTEND_IMPLEMENTATION_PLAN.md) · [Status dashboard](../IMPLEMENTATION_STATUS.md) · [Backend OpenAPI](../../../api-lms-v2/docs/api/cp11-cp12.openapi.json)

## 1. Tujuan

FE00 membangun fondasi yang wajib dipakai seluruh fitur v3. Checkpoint ini belum mengimplementasikan workflow akademik dan tidak mengklaim integrasi identity/Class selesai.

Exit FE00 menghasilkan:

- struktur Next.js v3 yang modular dan buildable;
- same-origin typed API transport tanpa browser auth token;
- OpenAPI snapshot, code generation, mock, dan contract drift checks;
- application shell serta design primitives yang reusable;
- i18n Bahasa Indonesia, state components, dan accessibility baseline;
- unit/component/E2E harness serta CI quality gate.

## 2. Dependency dan stop condition

### Dependency masuk

- Branch frontend `fe-v3` dan package lock yang dapat direproduksi.
- OpenAPI CP11–CP12 sebagai initial contract snapshot.
- Next.js 16.2.9 local documentation pada `node_modules/next/dist/docs/`.
- Keputusan same-origin proxy dan cookie/CSRF dari master plan.

### Stop condition

Hentikan dan catat blocker bila:

- pengerjaan berada di branch selain `fe-v3`;
- install dependency mengubah major Next/React tanpa scope terpisah;
- package registry/network tidak tersedia dan lockfile tidak dapat diperbarui secara valid;
- OpenAPI snapshot tidak dapat diparsing atau generated output tidak reproducible;
- solusi memerlukan localStorage/Bearer/query auth fallback;
- mock dapat aktif pada production build;
- existing user change ditemukan overlap dengan file yang akan diganti.

Backend yang belum lengkap bukan blocker untuk foundation atau mock contract FE00. Backend gap dicatat, tidak disamarkan dengan endpoint legacy.

## 4. Urutan implementasi

### Step 1 — Bekukan baseline dan dependency

1. Verifikasi branch, clean worktree, Node/npm version, Next/React versions, dan package lock.
2. Simpan baseline lint, typecheck, build, file inventory, dan endpoint usage sebagai evidence sanitised.
3. Baca dokumentasi lokal Next.js yang relevan: project structure, Server/Client Components, authentication, rewrites, Vitest, dan Playwright.
4. Tambahkan dependency terpin untuk OpenAPI generation/fetch, TanStack Query, React Hook Form, Zod, MSW, next-intl, Vitest/RTL, Playwright, dan accessibility checks.
5. Tambahkan script non-watch: `typecheck`, `test`, `test:coverage`, `test:e2e`, `contract:generate`, `contract:check`, dan `check`.

**Gate:** fresh dependency install berhasil dari lockfile dan tidak ada upgrade major framework yang tidak direncanakan.

### Step 2 — Buat struktur App Router v3

1. Buat route groups `(public)`, `(auth)`, dan `(workspace)` serta root error/not-found/loading boundaries.
2. Buat workspace layout dengan placeholder actor, sidebar, Class switcher, breadcrumbs, mobile navigation, dan content slot.
3. Buat private feature folders sesuai boundary master plan.
4. Pindahkan provider global ke komposisi minimal: theme, i18n, query client, tooltip, toaster.
5. Page default tidak boleh memanggil API legacy.

**Gate:** seluruh route skeleton dapat dirender, dinavigasi dengan keyboard, dan tidak mengimpor dashboard monolitik lama.

### Step 3 — Bangun API dan contract boundary

1. Salin initial OpenAPI v3 ke `contracts/` beserta backend commit, source path, checksum, dan status `PARTIAL_LOCAL`.
2. Generate TypeScript types secara deterministic; generated file tidak diedit manual.
3. Buat server transport untuk authenticated initial reads dan browser transport ke `/api/v3` untuk query/mutation.
4. Implement normalized `ApiError`, request ID, timeout/abort, `401/403/404/409/413/422/429/503`, dan safe unknown error.
5. Implement helpers untuk CSRF, idempotency key per intent, resource version, job polling, dan retry classification.
6. Tambahkan ESLint restriction agar domain component tidak memakai global `fetch` atau server-only env.
7. Hapus `window.fetch` interceptor serta seluruh pembacaan/penulisan `auth_token` dari foundation yang aktif.

**Gate:** tests membuktikan tidak ada Authorization header, localStorage token, query credential, unsafe retry, atau server secret di client bundle.

### Step 4 — Siapkan mock dan fixture matrix

1. Buat MSW server untuk Node tests dan worker hanya untuk opt-in local development.
2. Buat actor fixtures: Site Admin, Teacher, Student, Teacher+Student, Facilitator, dan outsider.
3. Buat Class fixtures: DRAFT, PUBLISHED, CLOSED, ARCHIVED; enrollment ACTIVE, SUSPENDED, dan ENDED.
4. Buat response fixtures untuk loading/empty/success/forbidden/not-found/conflict/validation/rate-limit/unavailable/job-partial.
5. Validasi fixture terhadap OpenAPI/schema dan tandai endpoint yang masih `MOCK_ONLY`.
6. Production config harus melempar error bila flag mock aktif.

**Gate:** fixture invalid menggagalkan CI; production build tidak memuat service worker mock.

### Step 5 — Design system, i18n, dan UI states

1. Normalisasi brand tokens, typography, spacing, radius, focus, semantic status colors, dark mode, dan reduced motion.
2. Self-host Lexend Deca dan Inclusive Sans dengan bukti lisensi; gunakan fallback system bila asset belum disetujui.
3. Buat message catalog Bahasa Indonesia dan helper typed translation key.
4. Siapkan reusable page header, filter bar, data table/card fallback, form field, confirmation dialog, status badge, skeleton, empty state, error panel, forbidden, read-only, conflict, job progress, dan retry notice.
5. Hindari domain logic pada `components/ui`; capability logic berada pada workspace/feature layer.

**Gate:** Story/test page internal atau component tests mencakup seluruh standard state, keyboard focus, contrast, dan 360 px layout.

### Step 6 — Test harness dan CI

1. Konfigurasi Vitest + Testing Library untuk synchronous components, hooks, schemas, dan transports.
2. Konfigurasi Playwright terhadap production build; async Server Components diuji melalui E2E.
3. Tambahkan accessibility assertions dan minimal Chromium journey; Firefox/WebKit menjalankan smoke routes yang disepakati.
4. Tambahkan CI order: install locked dependencies → contract check → lint → typecheck → unit/component → build → E2E.
5. Simpan artifact test yang sanitised; screenshot/traces hanya pada failure dan tidak boleh memuat credential.

**Gate:** seluruh command lulus dari fresh checkout dan tidak memerlukan network font fetch atau backend production.

### Step 7 — Closure dan handoff FE01

1. Jalankan semua QA FE00 pada source dan contract hash final.
2. Update `docs/IMPLEMENTATION_STATUS.md` dan bagian evidence checkpoint ini.
3. Inventarisasi sisa import/route/config legacy yang belum dihapus; tidak boleh aktif pada workspace v3.
4. Buat `docs/checkpoints/FE01.md` dengan frozen identity browser contract dan test matrix.
5. FE01 tidak dimulai sebelum hasil FE00 terbaru tetap hijau.
