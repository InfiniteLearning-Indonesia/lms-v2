## 1. Tujuan

FE06 menyiapkan operasional pembelajaran yang tetap terikat pada Class: jadwal pertemuan, catatan kehadiran dan koreksinya, pengajuan izin dengan bukti private, review izin, kasus disiplin/SP, periode logbook fleksibel, entry/revision/review, serta histori group dan personal mentor.

UI-first tidak mengubah status backend. Production harus fail closed tanpa fixture atau request M11–M12 yang belum ada.

## 2. Keputusan product dan UX yang dibekukan

- FE06 hanya memakai dua route utama yang sudah tersedia: `/attendance` untuk pertemuan, kehadiran, izin, dan SP; `/logbook` untuk periode, entry, review, group, dan mentor. Tidak ada menu sidebar tambahan.
- Student dan pengelola menerima projection actor-scoped yang berbeda. Keberadaan field projection dan contextual capability menentukan control; nama role, specialization, atau Site Admin label bukan authorization.
- Attendance tidak menganggap record yang hilang sebagai `ABSENT`; state `UNKNOWN` harus tetap berbeda.
- Surface Mentee hanya menampilkan kalender jadwal dan status kehadiran miliknya. Form izin, SP, rekap cohort, dan kontrol input tidak dirender pada projection Mentee.
- Teacher memakai dua mode: **Input & Kalender Kehadiran** dan **Rekap Kehadiran Bulanan**. Teacher memilih tanggal meeting sebelum meninjau roster; koreksi tidak menimpa revision sebelumnya dan final command menunggu version/receipt backend.
- Rekap bulanan merupakan typed backend projection berisi total/status dan detail Mentee. Persentase authoritative tidak dihitung ulang dari card atau roster di browser.
- Pengajuan/review izin hanya ditampilkan pada surface Teacher. Requester tetap harus diturunkan backend dari session pada contract final; bukti tetap private dan tidak dianggap aman sebelum lifecycle M06 mengizinkan.
- `PENDING` tidak sama dengan approved dan tidak otomatis mengubah attendance. Review approve/reject hanya muncul dari capability khusus dan final command tetap disabled.
- SP selalu Class-local. UI wajib menyatakan SP tidak otomatis menonaktifkan akun global atau akses pada Class lain. Correction/resolution mempertahankan history.
- Periode logbook tidak diasumsikan bulanan atau empat bulan. Label, tanggal, deadline, timezone, overlap policy, dan open/closed state berasal dari response backend.
- Draft, submitted, revision-required, dan accepted adalah state berbeda. Revision lama dan feedback mentor tidak ditimpa.
- Reviewer ditentukan capability serta assignment history yang efektif; bukan string role/profile. Reassignment tidak menghapus review dan entry lama.
- Group dan mentor pada FE06 bersifat konteks/history read-only. Create/reassign group/mentor tetap dependency M05/M12 dan tidak diaktifkan tanpa contract canonical.
- Surface pengelola memakai progressive disclosure: ringkasan → filter/meeting atau entry selection → detail. Wide table berubah menjadi card pada mobile; target control minimum 44 px.
- Seluruh copy baru berada pada katalog `next-intl`. Tidak ada status sukses palsu atau business mutation selama contract belum tersedia.

## 3. Scope

### 3.1 Masuk scope

- Actor-scoped typed view model dan capability policy untuk attendance serta logbook.
- Kalender Mentee read-only; kalender/input roster Teacher, explicit unknown state, revision/correction metadata, serta typed monthly recap projection.
- Private evidence state, Teacher reviewer inbox, decision reason, dan pending/approved/rejected/revision-required presentation.
- Class-local SP list, version/correction/resolution state, dan disabled authoring command.
- Flexible logbook periods, learner entry editor, immutable revision context, submit/revise/accepted presentation.
- Review inbox, feedback form shell, accept/request-revision command state, group context, dan mentor assignment history.
- Development-only fixture, production dependency state, component/model/E2E tests, responsive/accessibility/security checks.

### 3.2 Di luar scope

- Implementasi atau perubahan repository backend M11–M12.
- Global account suspension, self/foreign review, forged requester, inferred absence, auto-approved permit, destructive history rewrite.
- Group/mentor assignment mutation, attendance-driven completion calculation, notification delivery, report/export, payroll, geolocation, biometric attendance, atau QR check-in.
- Public proof URL, browser token/storage, invented endpoint/payload/query syntax, atau success receipt lokal.

## 4. Contract handoff minimum

| Area | Contract canonical yang dibutuhkan |
|---|---|
| Identity/ancestry | Class, meeting, enrollment, attendance revision, permit, case, period, entry revision, group, mentor-assignment ID dan ownership |
| Reads | Actor-scoped meeting/attendance, roster, permit inbox/detail, SP history, periods, learner entries, review inbox, effective mentor/group history |
| Commands | Meeting/exception, mark/correct attendance, request/revise/cancel permit, approve/reject, create/correct/resolve SP, configure period, save/submit/revise/accept logbook, reassign mentor/group |
| Capability | Separate read, write, review, discipline, period-config, logbook-review, dan mentoring capabilities yang contextual |
| Concurrency | Version/ETag, unique meeting+enrollment, immutable revisions, stale `409`, idempotency, durable command receipt |
| Time policy | Server timezone, meeting exception, period boundary/deadline, overlap validation, allowed transition timing |
| Private proof | FileAsset identity/state, scan result, attach eligibility, authorized access, expiry, denial reason |
| Errors/security | Typed `401/403/404/409/413/415/422/429/503`, safe detail, CSRF bootstrap/refresh, cookie credentials, no secret URL/storage/Bearer |

Backend M11 dan M12 masih `NOT_STARTED`, `0/5`, dan `NOT_RUN`; frontend tidak boleh menganggap tabel di atas telah tersedia di OpenAPI.

## 7. Stop condition

- Jangan mengaktifkan final command atau transport sampai OpenAPI, capability, CSRF, version/idempotency, receipt, dan error semantics direview.
- Jangan mengubah `UNKNOWN` menjadi `ABSENT`, `PENDING` menjadi approved, atau menghitung outcome M10 di browser.
- Jangan menampilkan permit/SP/logbook/mentor data lintas Class atau projection actor.
- Jangan menyimpan proof/signed URL/token pada browser storage atau Authorization header.
- Jangan mengubah backend, melakukan deployment, atau mengklaim FE06 completed dari UI-first.
